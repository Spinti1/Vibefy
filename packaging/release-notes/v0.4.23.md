Spotify sign-in is more resilient to fresh-system certificate stores and reports clearer connection errors.

## Fixed
- **HTTPS trust on fresh installations.** Mozilla public roots are bundled alongside native OS roots. HTTPS certificate and hostname validation stay enabled, and configured proxies remain respected. This addresses one possible source of connection failures; the reported remote machine has not been directly tested.
- **Safe token connection retry.** A failure while establishing the connection retries once after 250 ms. A token POST that may have reached Spotify is not explicitly replayed. Requests have a twenty-second timeout.
- **Useful sign-in errors.** Certificate, DNS, proxy, timeout and interrupted connections receive separate messages without exposing authorization responses, request data or raw credential-bearing URLs.

The Spotify Client ID, permissions and callback URI are unchanged. These changes do not bypass Spotify application access restrictions.

Windows Setup remains unsigned because no verified code-signing identity is configured. SmartScreen warnings cannot be removed by application code; signing can build publisher reputation but does not guarantee immediate removal of warnings. See https://learn.microsoft.com/en-us/windows/apps/package-and-deploy/smartscreen-reputation .
